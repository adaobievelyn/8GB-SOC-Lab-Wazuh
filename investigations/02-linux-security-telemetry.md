# Investigation 02 — Linux Security Telemetry

## Objective

Examine security telemetry generated by the monitored Linux endpoint and understand how host activity appeared inside Wazuh.

The investigation focused on confirming telemetry collection, reviewing authentication/session-related activity and using Wazuh event views to inspect Linux security events.

## Environment

- Wazuh Manager: Ubuntu Server 22.04
- Linux endpoint: Lubuntu
- Virtualization: VirtualBox
- Host system: 8GB RAM
- Network: Bridged local lab network
- Environment type: Controlled personal SOC lab

## Evidence Observed

The Linux endpoint was successfully enrolled with the Wazuh Manager and generated security telemetry visible through Wazuh.

The collected evidence included Linux host and authentication/session-related activity.

Wazuh event views exposed information such as:

- Agent identity
- Endpoint information
- Event timestamp
- Rule description
- Rule level
- Security-event context
- Authentication/session information
- Host-related event metadata

The screenshots also show PAM-related login/session activity among the Linux security events.

## Investigation Process

### 1. Confirm telemetry source

I verified that the Linux endpoint was connected to the Wazuh Manager and actively reporting events.

This was important because an analyst needs to confirm the source and health of telemetry before relying on it during an investigation.

### 2. Isolate Linux events

I used Wazuh's event views and filtering capabilities to focus on events associated with the Linux endpoint.

This reduced unrelated Windows and manager-side activity.

### 3. Review authentication and session activity

I examined authentication/session-related Linux events, including PAM-related activity visible in the collected telemetry.

The purpose was to understand:

- What user/session activity Wazuh recorded
- How Linux authentication events were represented
- Which contextual fields were available
- How individual events related to activity occurring on the endpoint

### 4. Inspect rule context

For relevant events, I reviewed Wazuh's rule description and associated security context.

This provided an additional classification layer above the underlying Linux event.

The rule context was treated as analytical metadata rather than automatic proof of malicious behavior.

### 5. Correlate endpoint activity with telemetry

Where activity was deliberately generated in the lab, I compared what occurred on the Linux endpoint with the corresponding Wazuh event stream.

This helped validate that endpoint activity was reaching the monitoring platform and could be investigated centrally.

## Analyst Assessment

The Linux investigation demonstrated that the Wazuh environment provided centralized visibility into security-relevant host activity from the monitored endpoint.

It also reinforced an important SOC principle:

> A security event is an observation that requires context, not an automatic conclusion about intent.

For example, a login/session event may be completely legitimate or may form part of suspicious activity.

The event becomes more meaningful when considered alongside:

- Account identity
- Timing
- Source
- Related events
- Expected user behavior
- Additional endpoint or network evidence

## What This Investigation Demonstrates

## What the Evidence Does Not Establish

This investigation does not establish:

- A real external compromise
- Malware execution
- Unauthorized persistence
- Enterprise Linux fleet monitoring
- Production incident response

The evidence supports hands-on Linux telemetry monitoring and security-event investigation in a controlled lab.
