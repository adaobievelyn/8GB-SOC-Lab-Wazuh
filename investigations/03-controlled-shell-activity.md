# Investigation 03 — Controlled Listener/Shell Activity

## Objective

Generate a known shell/listener interaction inside the controlled lab and examine the security telemetry surrounding that activity in Wazuh.

This case was designed to compare known endpoint behavior with what the monitoring platform recorded.

It was not a real intrusion.

## Environment

- Wazuh Manager: Ubuntu Server 22.04
- Monitored Linux endpoint
- VirtualBox
- Bridged local lab network
- Controlled listener on TCP port 4444
- Host system: 8GB RAM
- Environment type: Controlled personal security lab

## Controlled Activity

A listener was started on TCP port **4444** inside the lab.

A controlled shell connection was then initiated from another lab endpoint.

The terminal evidence shows:

- A listener operating on port 4444
- An inbound connection from another host on the local lab network
- An interactive shell becoming available
- Basic commands being executed to confirm the shell context

This activity was deliberately generated for security-monitoring and investigation purposes.

## Investigation Process

### 1. Establish known activity

Because I generated the activity myself, I knew:

- The approximate time of execution
- The systems involved
- The destination port
- The expected connection behavior
- That the activity was authorized within the lab

This created a useful reference point for examining the resulting telemetry.

### 2. Confirm host-level behavior

I first confirmed the listener and shell activity at the endpoint/terminal level.

This established that the expected interaction actually occurred before attempting to interpret SIEM data.

### 3. Review Wazuh telemetry

I then reviewed Wazuh security events associated with the lab systems around the relevant activity.

I used Wazuh event views and filters to reduce unrelated telemetry and inspect relevant events.

### 4. Inspect event context

For relevant security events, I examined available information such as:

- Endpoint / agent identity
- Timestamp
- Rule description
- Rule level
- Event context
- Host-related metadata

The purpose was to determine what Wazuh actually recorded rather than assuming that the SIEM would describe the activity in the same terms used at the endpoint.

## Important Analytical Boundary

The terminal evidence establishes that controlled listener/shell activity occurred.

That does **not automatically mean that every Wazuh event observed during the same period represents detection of a "reverse shell."**

A distinction must be maintained between:

**Host-level observation**

A controlled shell connection occurred over port 4444.

and:

**SIEM-level observation**

Wazuh recorded security telemetry generated by the monitored systems around the controlled activity.

Unless a specific Wazuh rule explicitly classifies an event as a reverse shell, I do not describe that event as proof that Wazuh detected a reverse shell.

This distinction prevents an analyst from turning correlation or timing into an unsupported conclusion.

## Analyst Assessment

This exercise demonstrated a useful security-monitoring workflow:

**Known activity → endpoint confirmation → telemetry review → filtering → event inspection → evidence-bounded assessment**

Because the activity was controlled, I could compare known ground activity with what appeared in the SIEM.

That made the exercise useful for understanding both:

- What Wazuh could show
- What Wazuh did not necessarily prove

## What This Investigation Demonstrates

- Controlled security testing
- Listener/shell activity generation in a lab
- Endpoint behavior validation
- Wazuh event review
- Event filtering
- Security-telemetry interpretation
- Correlation of known activity with monitored telemetry
- Separation of direct evidence from analytical inference

## What the Evidence Does Not Establish

This case does not establish:

- A real external attack
- Malware execution
- Unauthorized command-and-control
- Attribution to a threat actor
- Production incident response
- That Wazuh explicitly classified every related event as reverse-shell activity

Those would require additional evidence.
